# 极致上下文优化：逐对话显式启用的实验选项

这是 Skill 的工作约定，**不是客户端原生开关或底层请求过滤器**。默认关闭，不因“慢”“修图片”“压缩一下”或一次其他对话授权自动启用。不保证永不遗忘、不降低所有延迟；满载、鉴权、网络故障另行处理。

## 确认门槛

1. 定位唯一目标，检查当前回合空闲；忙时等待自然完成，不中断。沿用主 Skill 的自目标/祖先保护。不得把当前聊天对本模式的允许泛化到其他对话。
2. 必须将 [extreme-consent.txt](extreme-consent.txt) 中的提示**原封不动**发给用户，再单独询问是否仅对目标对话启用。用户已看到相同原文并明确确认本次目标时复用确认，避免重复询问。
3. 用户同意模式，不等于同意代发维护消息、压缩或测试消息。若需要第一方 `send_message_to_thread`，先获得明确的发消息许可；这是用户可见消息，不后台注入隐藏指令。目标模型及推理强度保持原样，调用时省略 model/thinking。
4. 不改项目代码/AGENTS、业务表格、全局设置、插件开关或其他会话，不执行原业务待办，不上传私有快照。没有适用工具或权限时交付待执行方案，不擅自扩权。

## 备份与留档

在仓库和 Skill 以外选择私有持久目录 DATA，不搬动旧图片备份。通过第一方工具确认空闲后运行：

```bash
python3 "$SKILL_DIR/scripts/snapshot_context.py" snapshot \
  --thread "$TARGET" --current-thread "$CURRENT" --data-dir "$DATA"
```

脚本只读 Codex：完整 JSONL 快照 `before-maintenance.jsonl`、最新 checkpoint 后实际存在的工具结果 `available-tool-results.jsonl`、字节索引 `tool-index.json`、大小/token 基线 `baseline.json`。已有结果可能原本就被截断，标记只是线索，不是完整性证明。源文件改变时停止维护；保留快照并等待空闲后选新目录。禁止把本地重建 JSON 字节数说成真实网络请求体。

索引只覆盖最新 checkpoint 后的工具结果。需要更早的中间过程时，先依据 call_id/时间/工具名在完整备份 `before-maintenance.jsonl` 中逐行定向检索，再抽取匹配原记录另存并核对字节；不要把整个备份灌回模型。备份也未记录或原本截断的部分应标注缺口，不声称恢复。

发送简短维护指令，让目标读取模式规则，并仅在 DATA 创建 `context-anchor.txt`：
- 当前目标、已核实规则/数值与证据位置；事实、估算和待确认项分开；
- 已完成动作、未完成事项与禁止重复执行的外部写入；
- 关键文件、表格、截图/原图路径和已有修复目录；
- 本实验模式已明确确认，仅适用于此对话；关闭方式及复盘方式。

不要用父代理的猜测填充业务事实。优先由拥有完整上下文的目标整理，并以现有记录抽查若干关键事实。维护回合不得继续业务、修改表格、提交/推送/部署或自行改写会话 JSONL。

## 输出规则

- **完整执行，精简回传**：读取、计算、检查、测试照常做；原始工具结果先完整落文件并核实可读，再输出足够支撑结论的摘要、异常、关键字段和绝对路径。不以“优化”为由漏做检查或只看日志头尾就宣布成功。
- 不设一刀切字符限制。错误、警告、关键数值、影响判断的上下文、未解决问题与证据引用必须保留。信息对当前推断必要时直接展开。
- 对大量配置、表格、日志先用程序在完整数据上筛选/统计，保留原始结果及查询方式，回传相关行而非整表；若导出完整结果的接口不存在，说明记录缺口，不宣称完整留档。
- “中间过程”指可记录的工具输入/输出，不是模型内部思维链。秘密/个人数据按最少必要原则留档，不能为了完整日志扩大收集或外传范围。
- 用户说“读取中间过程”/“复盘完整日志”时，读取索引定位原始记录，核对来源再解释；必要证据缺失就明说，不补造。模型发现结论缺证据时也应主动回读，不强制等用户发特定口令。
- 用户说“关闭极致优化”即可停用本约定，恢复常规输出；不要求另行确认关闭。关闭不会自动展开已经压缩的历史，也不删除已存档资料。

## 压缩与验收

输出约定本身只控制**未来增长**，不会移除已进入上下文的工具结果。若用户也同意压缩：

1. 只通过已确认可用的原生压缩入口操作；聊天消息 `/compact` 不保证被连接器当成指令。必须观察新的 `compacted` 事件/正式压缩通知与后续 token 用量才称为成功。
2. 缺少原生入口时停在规则已启用，说明“尚未压缩”，请用户在应用中触发。不得启动第二个会话写入进程、伪造 compaction item、截断 JSONL、裁剪加密摘要、改 SQLite 或盲目修改全局阈值。
3. 压缩后用一条获许可的验证消息检查关键事实与本地过程索引读取；问题范围固定、不带答案，禁止恢复业务。记录模型、推理强度、token/JSON 口径、响应耗时；不把不同业务的耗时比称作受控性能提升。
4. 分开报告：确认已收到、规则已采用、资料已留档、原生压缩是否成功、过程回读是否通过。状态文件 `mode.json` 的 activated 只在目标明确确认规则后写入；它是维护记录，不是客户端配置。
5. 快照验证：
   ```bash
   python3 "$SKILL_DIR/scripts/snapshot_context.py" verify \
     --thread "$TARGET" --current-thread "$CURRENT" --data-dir "$DATA"
   ```
   若源历史已有新消息，不用旧整文件覆盖回滚。停用约定、保留备份，必要时按已验证资料补回缺失事实；压缩不声称“完全无损”。
